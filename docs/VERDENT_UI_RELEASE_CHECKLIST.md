# UI/IA一括改修 — Verdent最終検証・統合指示

対象ブランチ: `feat/real-user-validation-20261022`。このブランチの最新状態を取得し、**mainに直接変更せず**、下記の検証と必要な修正を同ブランチで行う。

## 今回の設計方針
- ネイビー基調のBtoB SaaS。ヒーローは簡潔な価値訴求＋公開デモ＋架空の確認状況プレビュー。
- ユーザージャーニー: `/` → `/getting-started` → `/demo` → `/result-guide` → `/evaluation-logic` → `/contact`。
- グレード・スコアよりも「未調査・証拠不足・次のアクション」を優先。
- 公開デモは固定データであり、AIの再判定や外部制裁照合を実行したかのように見せない。
- 公開情報の確認範囲と実際の該非判定・制裁照合・許可判断を混同させない。

## 必須検証
1. `npm ci`
2. `npx tsc --noEmit`
3. `npm run lint`（存在する場合）
4. `npm test`（存在する場合）と `node --test src/lib/user-acceptance.test.ts src/lib/landing-claims.test.ts`（TypeScript直接実行可能なNode環境に限る。実行不可ならtsx等の既存ランナーを使用）
5. `npm run build`（DB/API環境変数不足は明示し、コード不具合と区別）
6. Playwright等で `/`, `/getting-started`, `/demo`, `/result-guide`, `/evaluation-logic`, `/contact`, `/security`, `/about`, `/glossary`, `/learning` を 375px / 768px / 1440px で表示確認。
7. ヘッダーのメニュー開閉・Escape・フォーカス・各リンクの404・CTA遷移を確認。
8. デモで商品名・型番・仕向地・企業名を1文字変更するたびに、古い固定評価が非表示となることを確認。シナリオ再選択で復帰すること。
9. デモの固定シナリオで「実照合済み」「安全」「輸出可能」と誤認させる表現がないか点検。特にAグレードの説明、架空の制裁照合結果、根拠サマリーを確認。
10. 公開LPの『5分』『専門知識不要』『24時間モニタリング』『UBO/PEPs照合済み』など未実証の断定、メタデータ、JSON-LD、構造化データ、Aboutページを横断チェック。
11. ダーク/ライト配色で背景と文字色のコントラストを確認。既存`text-amber-300`など薄い文字色を白背景に置かない。
12. モバイルの水平スクロール、44px未満のタップ領域、重複ナビゲーション、sticky headerの重なりを修正。

## 修正時の制約
- API/認証/DBの仕様を推測して変更しない。
- 「未調査」はA判定とせず、判定保留または要確認にする。固定デモに実際の法令判断を混入させない。
- 新しいページは既存の`Header`, `SiteFooter`, `buildSeo`を再利用。
- ユーザーが公開を承認するまでmainマージ・本番デプロイしない。
- 検証結果はコマンド・実行環境・成功/失敗・修正コミット・残課題を一覧で報告する。
