# 実ユーザー受入テスト計画（商用化前）

この文書と `tests/fixtures/export-risk-user-scenarios.csv` は、実際の輸出担当者が使う際のリスクを検証するための受入基準です。**シナリオの追加はテスト合格を意味しません。** 架空企業・架空制裁対象は必ずテスト用と表示し、実際の制裁データとの照合結果として扱わないこと。

## 実行手順
1. ステージング環境に本番同等の認証設定を用意し、ダミーデータだけを使用する。
2. CSVのS01〜S30を順に実施し、各行に結果（PASS/FAIL/BLOCKED）、画面証跡、担当者、実行日時、Git SHAを記録する。
3. 制裁・企業照合・輸出規制分類は公的な一次資料との突合を別途実施する。AIの回答だけで正解扱いしない。
4. S04/S06/S07/S13/S16/S17/S18/S19/S25/S26/S27/S28をリリース阻止項目とする。
5. PDFと画面の一致、アクセス制御、エラー時の挙動を自動化する。実行できない項目は未検証として残す。

## リリース判定
- 必須項目にFAIL/BLOCKEDがないこと。
- 未調査は安全を意味しない。制裁照合失敗や最終需要者不明なら承認可能と表示しない。
- 結果に根拠URL・確認日時・適用法域・未調査事項を表示する。
- 認証を要する情報はサーバー側でテナント/所有者を検証する。
- 機微情報の取り扱い・保存期間・外部AI送信条件を明示する。

## LP文言の監査
現行LPに「専門知識は不要」「5分でチェック」「8観点」「該非判定支援」「制裁リスト調査」「UBO/PEPs確認」などの表現がある。各表現に対して実装状況、データ取得元、適用範囲、実測所要時間を記録し、未提供機能は「計画中」と明記する。輸出許可・法令適合の確定を示唆しない。
